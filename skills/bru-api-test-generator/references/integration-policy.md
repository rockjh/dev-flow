# API 集成边界

本 Skill 维护单模块 API 契约、Bruno 请求及其执行证据。跨模块或跨服务的完整业务链、消息消费、调度器、缓存与故障控制归 E2E 工作流；本 Skill 可以消费已验收证据，不能在 API 资产下复制 E2E 的 Python `common/`、fixture 框架或运行时实现。

请求形状、参数和响应协议来自离线 OpenAPI；业务条件、结果和错误语义来自 biz-flow 已审核资产。源码与运行时探针只能补充执行支持或报告实现偏差，不能反推业务预期。已有的设计映射缓存不是第二份业务事实来源。

API 请求从活动 Bruno 环境取得地址、上下文路径、Header、认证变量和文件引用。只配置当前目标，不切换到开发者默认地址或共享生产环境。网络预检和真实请求需要当前目标的执行授权；生成子代理不因需要“验证”而自行发送请求。

分别检查实际 HTTP 状态及设计定义的业务结果。传输成功但业务状态不符仍失败。只在设计和协议声明幂等语义、标识结构且执行授权覆盖时重试非只读请求；不能用无界重试、固定等待或观测值覆盖断言。

`flows.yaml` 仅表达设计支持的模块内有序 API 流程。每步引用真实 case，capture/use/absence 必须有实际 Bruno reporter 事件和顺序对账。异步结果需要设计支持的有界轮询及终止策略；一次提交加一次查询不能宣称轮询验收，顺序流程也不能宣称业务并发。

数据库只在 [database-access.md](database-access.md) 的两种明确理由下补前置数据或不可见状态。读取使用参数绑定和精确关联键；准备及清理要求独占命名空间、分别授权、幂等创建和可验证恢复。禁止直接写入最终预期状态来制造 API 成功。

消息发布、动态配置修改、全局缓存清理、调度触发、模拟和故障注入不由生成授权自动授予。缺少正式协议、来源证据、环境边界、隔离或恢复能力时停止相关执行；跨服务需求交由具备对应领域门禁的 E2E Skill，不在本 Skill 添加隐藏控制接口。

诊断保留非敏感的模块、case ID、方法、目标标识、关联字段名、实际状态及有界响应摘要。不得输出认证 Header、Cookie、密钥、完整连接字符串、原始敏感消息或完整数据库行。连接失败、业务结果不符、缺失下游结果和清理失败分别如实报告，不改为通过或无条件跳过。
