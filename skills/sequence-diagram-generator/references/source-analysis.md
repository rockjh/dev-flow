# Source analysis

Run `devflow sequence-diagram-generator init --project <absolute-root>`, then `discover --project <root> --mode code [--entry <qualified-symbol-and-signature>]`. Check inventory with `check --project <root> --run-id <id> --stage entries --full`.

The Skill's `../example/` contains a minimal amount-decision project, requirement proposal and revision-zero baseline. Copy that business project to an isolated workspace for practice; it contains no host execution or online publication records.

Discovery distinguishes directly registered entries from ordinary selected symbols. Unknown frameworks are not guessed. Prepare uses selected discovery IDs, repeated `--entry-id`, or explicit `--all-entries`, plus `--confirm`. The selected set, intent and execution mode cannot change afterward.

Python uses standard AST; the other adapters use pinned grammar packages, with separate JavaScript and TypeScript parsing. Installation supplies dependencies. Source bytes stay in analysis memory; persisted facts are redacted. Excluded directories include VCS metadata, dependencies, build outputs, caches and this domain's generated assets. Source/configuration fingerprints use sorted project-relative paths and raw byte hashes. Symlink/junction traversal outside the project stops.

Inspect actual capabilities and gaps rather than assuming grammar coverage. Static call resolution is conservative: project calls require a unique declaration, imported dependency calls remain boundaries, supported summaries have fixed semantics, and unknown calls affecting outcomes block. Dynamic imports/dispatch, unresolved overloads, incomplete exception origins, callback/channel completion and unexpanded Rust macros are examples of critical boundaries. No build, macro expansion or target execution is allowed.

Call instances have distinct contexts, even when they reference the same evidence. Recursion stays an explicit boundary. Coverage means discovered outcome-relevant exits and steps within the selected static scope; it does not prove every input or scheduling interleaving. Source/adapter changes require discover in a new run.

Frozen source ordering records bind each control arm's label and ordered step/control IDs separately from the document tree. Reordering complete IDs, relabeling an exit, continuing after all nested paths terminate, or citing another target's evidence fails delivery. Labels and requirement links must cite proofs belonging to their actual targets.

Verified narrow API forms include imported Java ExecutorService.submit with a declared Callable and an assigned Future.get on the same path; locally constructed, imported Node EventEmitter with direct synchronous on/once listeners and emit; and directly imported Python sqlite3.connect with literal execute statements and separate commit/rollback calls. Java varargs and post-name arrays retain complete signatures. Python parameter shadowing or rebinding and Rust use aliases are resolved conservatively. Async listeners, conditional waits, dynamic SQL and unresolved receiver types remain explicit critical boundaries. Fixed direct completion forms are supported when binding evidence is complete: Rust `std::thread::spawn` of a local zero-argument function followed by the same handle's unconditional `join`, and Go `go` of a local one-channel producer followed by the same channel's direct receive. These forms show dispatch/parallelism and observed wait/value without claiming arbitrary goroutine or thread termination. P-IDs identify issued persistence statements and transaction operations; issuing a statement never substitutes for commit or proves dependency internals.
