# Host handoff

Prepare returns the authoritative task-package path and digest. Read the core schema for TaskPackage/HostSubmission using installed `devflow schema`; never invent a receipt structure. Tasks bind run, task, scope, model and requirement identities. Host annotations may label facts, explain business meaning, map requirements and supply evidence-linked proposals. They cannot replace control edges, remove exits, invent code actions or downgrade fixed critical gaps. Evidence queries require a new adapter-validated run.

Native mode is default. Use actual child agents with lifecycle, start/end, tool and reclamation records. Each task needs exactly one successful result and receipt with matching package/result hashes. Agents are read-only toward target source, business assets, version file and manifest; only their own results may be written. CLI checks identities, structure and consistency; authenticity remains host-attested against actual session tool records.

Serial mode requires `--execution-mode serial --execution-approval <existing-session-reference>`, task-bound authorization, degraded=true, parallel=false and zero child agents. If native is unavailable, offer serial/stop once; reuse prior explicit authorization and do not silently downgrade. Receipt strings alone do not prove an agent ran.

Save the complete redacted submission to an explicit file and use `collect --project <root> --run-id <id> --results <absolute-file>`. A different submission for an already collected package requires a new run; an identical one is idempotent. Synthetic test receipts are fixtures and cannot be presented as actual host execution.
