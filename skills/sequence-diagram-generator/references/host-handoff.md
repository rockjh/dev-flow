# Host handoff

Prepare returns the authoritative task-package path and digest with `handoff_state=tasks_prepared`, `host_capability=unknown` and `execution_evidence=not_started`. CLI cannot access session tools. Continue in the coordinating session: read `devflow schema sequence-diagram-generator.task-package` and `devflow schema sequence-diagram-generator.host-submission`, then the package itself. Only protocol/schema 4 is supported; a run outside that contract must be prepared again.

Each task binds run, scope, model and requirement hashes, questions and an exclusive relative `result_path`. `source_project` and `source_commit` identify the committed source; `facts` contains frozen code evidence. Read committed files with the recorded commit when further inspection is needed, never modified or untracked source. `handoff_root` is under the run in `~/.local/state/devflow/artifacts/sequence-diagram/runs/`; manifests and handoff files do not belong in the analyzed project's root. Host annotations may label facts, explain business meaning, map requirements and supply evidence-linked proposals. Source tasks require evidence-linked labels and independent analysis diagnostics; blank label text or diagnostic entries are rejected. Labels may target only the assigned scopes' symbols, steps and controls; evidence mappings also contain operations and branch exits, which are not label targets. When scopes share a symbol, the coordinator assigns its label to one task before dispatch; other tasks may explain the shared call in diagnostics. Requirement tasks receive only the selected `segment_ids`; the full input snapshot stays frozen, while mapping and coverage account only for the selected subset. They cannot replace control edges, remove exits, invent code actions or downgrade fixed critical gaps. Evidence queries require a new adapter-validated run.

Native execution procedure:

1. Inspect actual session tools and constraints. No brand CLI, PATH or executor environment variable establishes session capability. Dispatch the first real task to validate startup. For example, a host exposing `collaboration.spawn_agent` expects a direct tool invocation; other hosts can expose different names or calling conventions. Python CLI never launches or impersonates these tools.
2. Pass the exact frozen task, package hash, result schema and exclusive output location to a native child. It must independently inspect source evidence and return HostTaskResult. Read-only restrictions cover source, business assets, version file and manifest. Only its own handoff directory is writable. Report `permission_enforcement` truthfully: `shared_workspace_instructions` is a prompt constraint, while `host_sandbox`, `worktree` and `staging_patch` require their actual protection. CLI also compares prepared worktree source/config and protected asset hashes, preserving pre-existing user edits and rejecting new writes.
3. Save the returned child ID and real tool/session references. Start independent tasks within free slots, accounting for existing agents; wait, reuse idle agents or batch when full. No nested agents to evade slots. “Running” and “idle” are different from failed and reclaimed. Do not turn a task failure into a startup capability error.
4. Wait using the host's actual wait/message/continuation tools. Task results bind `attempt`; each task gets one successful result and one successful receipt. Failed receipts retain `error`, their attempt, child and references, with an empty `result_hash`. Attempts start at 1, advance consecutively and stop at first success. Correct formatting within the same frozen inputs; do not invent a missing business conclusion. Changed source/facts require a new run.
5. Convert the returned results without changing their conclusions. Use `time_source=host` only for actual host lifecycle times; `coordinator_observed` identifies the main agent's observations. Empty times with `unavailable` are valid. `reclaim_state=unsupported|not_observed` requires empty `reclaimed_at`; `reclaimed` requires an actual returned release record, time and tool reference. A completed task is not proof that its child was closed.
6. `mode=native` is independent of parallelism. One slot, one task, dependencies or quick completion can yield valid native sequential execution. Coordinator dispatch/receipt times alone do not prove overlap. For `parallel=true`, use actual host start/end intervals or `active_observations`: an actual status snapshot observing at least two distinct launched task owners running together, with `observed_at`, `active_task_ids`, corresponding `active_attempts` and `active_child_agent_ids`, `tool_reference` and `time_source`. Bind the actual attempts, including failed, interrupted or timed-out attempts and excluding startup failures. Check every available start/end bound against snapshots from the same time source; partial timestamps remain valid. A child cannot own overlapping host intervals across any started attempts. A failed attempt's snapshot cannot prove its retry overlapped. Never delay tasks to manufacture overlap. Count `completed_child_agents` from unique successful child IDs, including reused agents only once.
7. Collect, check, verify and accept. CLI validates task/run/input/result binding, attempts, exact coverage, unique child counts, declared observations, frozen facts and protected writes. `host-execution-report.json` records `record_origin=host-attested` and `trust_boundary=structure-and-consistency-only`: the main agent must match references against this session's actual tools. A valid JSON/UUID is no proof of real execution. Fixtures are explicitly marked and rejected by production handoff validation.

For a schema-based field conversion example, read [host-handoff-example](host-handoff-example.md). The example performs no spawning and is not a production receipt.

Serial mode requires `--execution-mode serial --execution-approval <existing-session-reference>`, task-bound explicit authorization, `degraded=true`, `parallel=false` and zero children. “Direct generation” alone does not authorize it. If native tools are missing, prohibited or unrecoverably fail to start, preserve that distinction and offer serial/stop once; reuse prior explicit authorization. The main agent must truly analyze the source. Static inventory copies are not analysis. A new serial run preserves diagnostics of any earlier native run; never rewrite prior native history as zero children.

Save the complete redacted submission under the state run and use `collect --project <root> --run-id <id> --results <absolute-file>`. Rejected submissions and collection errors preserve prepared state for correction, without writing business assets or advancing the baseline. Valid explicit failed attempts bound to this run/package/task remain immutable on later collections, including after a domain-gate failure; retain them and increment the retry attempt. Foreign or invalid failure records cannot establish this history. Conflicting retry submissions remain as `attempt-history-conflict-*.json` diagnostics and cannot replace earlier failure evidence. A different submission after collection requires a new run; an identical one is idempotent while inputs remain current. Report preparation, actual child execution, collection and domain acceptance separately, and include the execution report, manifest and session references. Missing required tasks or domain failures prevent an overall success claim.
