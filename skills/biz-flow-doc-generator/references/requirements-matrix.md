# Biz-flow 两阶段验收矩阵

第一阶段入口目录和第二阶段业务分析分别验收。证据必须来自本次源码；CLI schema、Markdown 与外部 manifest 一致才能宣布完成。

| 阶段 / 需求 | 必需门禁 | 权威证据 |
| --- | --- | --- |
| 1 全量注册扫描 | 扫描源码/配置及适用 HTTP、消息、任务、事件、导入、CLI、平台注册；报告不支持/动态注册范围 | 扫描范围、适配器及注册位置 |
| 1 真正业务入口 | 有注册及业务用途证据；辅助方法/线程池不独立计数；同触发链去重，独立恢复/消费保留 | 候选触发和身份、排除依据 |
| 1 全量对账 | 全候选归属/排除/待识别相加一致；业务入口总览=最终模块入口章节，无遗漏且单一归属 | ID 集合及数量对账 |
| 1 业务化归组 | 一级业务域单一 Markdown，域内全部场景/渠道/触发按入口章节，不按动作拆文件；跨域入口归属主结果域；文件名用自然业务对象加核心职责、关系或生命周期，长域概括功能族，不固定后缀或堆动词；业务描述参考 Swagger 和源码说明归纳能力，独立于文件名，合并同类接口并允许标点分段，完整入口另表保留 | 源业务词汇、项目文档命名风格、模块映射、三列表格 |
| 1 持久化与展示 | 总览保留完整清单，模块骨架仅有标题；对话直接展示完整三列概览和类别排除/疑点，不只给链接 | 总览、模块骨架、CLI 输出 |
| 1 独立完成 | `check --stage entries` 独立通过；不展开深调用链/分支/存储、不需要代理；疑点仅入口触发/身份/用途/归属 | discovery 内容、入口目录 check 报告 |
| 1 确认 | 分类只确认一次，已有授权有效；确认绑定 source/mapping fingerprint，调整不影响其他归属 | 确认标记、映射 fingerprint |
| 2 有界真实委派 | 每确认入口一个只读结果；按宿主槽位分批，native 顺序执行有效；模块唯一写入者验证合并后提交 | 冻结任务、实际 child/attempt、工具引用、观察来源及实际回收状态；host-attested 一致性报告 |
| 2 源行为证据 | 仅入口可达链；所有结果相关分支、读写、外部副作用、异步、结果、活动错误完整；缺口通过类型化补证和新运行处理 | 冻结 entry_facts、源码证明、独立 analysis/annotations、验证的 evidence_requests |
| 2 问题范围 | 排除候选与无关源码不计行为未决；关键未决阻断受影响入口，整体不假成功 | 按阶段/入口的 unresolved、模块状态 |
| 2 图与结构 | 每入口业务标题、触发、功能、sequenceDiagram/autonumber、分支矩阵；控制树和异步有据；冻结 flow 及真实参与方保持调用/返回顺序、控制嵌套及各路径响应，无统一假成功 | 最终 Markdown、entry_facts.flow、check及源码时序复核 |
| 2 存储与覆盖 | 真实对象及中文标签；fact/step ID 在结果、图注释、矩阵、manifest 一致；无存储不强加参与方 | 冻结事实与完整注释覆盖集合 |
| 2 prepare/collect | prepare 导出任务包，collect 校验运行身份、入口结果和执行证据；audit 不写最终文档 | 脱敏任务包、结果 manifest、文档哈希 |
| 2 宿主交接及失败 | 任务准备后主 Agent 接续启动、等待、收集；区分工具缺失/禁止、槽位不足、启动失败及任务失败；明确串行授权才降级 | 当前会话真实工具记录、serial_approval、mode/parallel/degraded、退出码；不探测品牌 CLI |
| 共同 安全与版本 | 安全路径、锁、单一归属、脱敏、sole JSON、外部 manifest；commit+dirty+fingerprint 真实 | 核心验证、版本及运行报告 |
| 共同 增量稳定 | 新增/变化/删除及共享依赖影响准确；未变内容稳定；check 后连续两次 verify stable=true 才推进基线 | Git 比较、覆盖、两次 verify |
| 共同 Mermaid 验证 | 文档验收必须实际渲染；缺少渲染器时明确只验证结构并阻断验收 | 渲染器或结构校验结果 |

入口目录成功不代表流程文档成功。证据不足不得猜测规则、泛化未知资源或伪造并行来满足表格。

5.2.1：全范围注册 coverage_gaps 独立阻断验收，数量对账不能代替覆盖证明；模块验收汇总不能替代全范围新运行。prepare/resume 的 behavior_report 按模块/入口保留绑定、来源、缺口和恢复动作。执行器类型不能证明调度/拒绝策略，未证明时 critical gap 保留。Windows 长子路径及内部目录别名由运行时和实际 IO 回归校验；缺少渲染器阻断文档验收。

仓内普通类的 this/super 构造链、实例字段及初始化块须按执行顺序对账；接收者求值不能遗漏构造副作用。private/static 调用不能误选子类同名方法，super 和继承方法引用不能丢失实际接收者。已证明抛出后的直线动作、赋值与响应不得继续生成；catch/finally 保留。库外父构造、静态初始化、复杂出口合流及未解析父 POM 继续阻断，不能把这些回归通过当作外部框架生命周期已实现。
